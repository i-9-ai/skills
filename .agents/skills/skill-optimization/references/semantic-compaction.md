# Semantic compaction of a skill

Use this route when reducing the context loaded to perform a skill's task, including a newly authored or synthesized package. The output remains an optimization candidate and record. “Lossless” is a requested goal, not a mathematical guarantee for natural language: report demonstrated preservation within the frozen coverage and environment. Byte-exact storage compression or a recoverable archive does not prove that an agent can act correctly from the smaller loaded route.

## Freeze the preservation contract

Before rewriting, retain an immutable complete baseline and inventory every meaningful semantic unit, including material in references, scripts and examples. Freeze task splits, critical criteria and a material cost threshold using the optimization loop. A new package can use its complete pre-compaction draft as baseline; do not skip that draft or claim improvement over an imaginary original. A synthesis plan supplies source mappings and resolved conflicts, not permission to accept untested compression.

Record each unit in the caller's optimization record:

| Field | Required content |
| --- | --- |
| ID and source | Stable ID, immutable package identity, file/section and precise claim; retain source hashes |
| Meaning | Actor/action, modality, scope, preconditions, negation, exceptions, numeric bounds and rationale needed to decide |
| Relationships | Precedence, ordering, dependencies, referenced definitions, input/output contracts and authority boundary |
| Evidence state | Confirmed, proposed, assumption or unresolved; preserve jurisdiction/version/date when material |
| Destination | Candidate file/section and loading condition, or equivalent canonical unit plus why truly redundant |
| Verification | Ordinary case and boundary/negative case with observable expected decision, output or refusal |

Cover required examples, recovery and failed approaches that constrain future decisions. “Reject” in a contribution matrix is not evidence that a necessary rule can disappear: justify its irrelevance or replacement under the approved target scope. Do not silently change that scope. Keep unresolved contradictory claims as blocked units until supported resolution; never compress them into a falsely certain rule.

## Rewrite and reconcile

1. Remove repeated expressions of the same scoped claim. Share one definition only when callers retain its scope, exception and authority. Do not merge two similar words with different meanings.
2. Prefer direct prose or a table when it preserves decisions. Keep the normal complete example and ordinary prerequisites together. Move independently needed branches into bundled references with explicit loading conditions; ship those references with the package. A missing companion or decoder is a dependency failure, not a reason to rely on prior knowledge.
3. Trace every baseline unit forward to its candidate destination. Then trace every candidate rule backward: flag additions, altered modality, broadened permissions and unsupported certainty. A one-way coverage checklist misses invented rules.
4. Follow each case's actual route from entrypoint through definitions, references, examples and fallback text. Reject dead links, ambiguous aliases, cyclic handoffs, unavailable dependencies or a loading condition that hides a rule on a route where it applies.
5. Count the full loaded route using the same tokenizer/version or labeled UTF-8 byte/character proxy for baseline and candidate. Include orchestration instructions needed for execution, duplicate/repeated loads, mandatory references, decode instructions and textual diagram fallbacks. Report per-case counts and navigation steps; do not average away a critical regression. Keep total package size separate. An audit ledger need not be loaded by a consumer; if the consumer needs it, count it.
6. Exercise tuning cases before selecting candidates, selection-validation cases only for selection, and the untouched final-acceptance set once for the selected candidate. Record actual artifacts and observed outcomes. Predetermined fixtures or static mappings alone do not establish agent behavior; label manual exercises, deterministic checks and fresh-context model runs separately.

## Example and refusal cases

A complete ordinary instruction for a synthetic report skill is:

> Read the supplied CSV with UTF-8. Reject missing `id` columns. Export only unique IDs. Default to preview; write `report.csv` only after explicit approval of that output. An approval for another file does not apply. On invalid input, return the offending row number without writing. Example: `id\n7\n7` previews one ID, `7`; approval of `report.csv` then allows that file to be written.

Two sources may repeat preview-first behavior while one adds the wrong-file exception. Keep one preview rule, the exception, the input/output contract, recovery and the complete example. A shorter “validate CSV and export IDs after approval” loses encoding, schema, deduplication, output identity and failure behavior; reject it even if its byte count is much smaller.

Freeze cases for ordinary deduplication/preview, missing schema, invalid row, approved correct output and approval for another file. Add a source conflict (one source permits immediate write), a missing dependency and a proposed claim presented as confirmed. Expected results must preserve refusal and uncertainty. Test shifted numeric boundaries and negations whenever present. Include a negative candidate for every changed critical dimension; verify the rubric rejects it instead of merely reporting fewer tokens.

## Acceptance and retained record

Accept only when all required units are reachable and equivalent under review, reverse tracing finds no unsupported change, all critical cases pass, and the frozen material cost threshold is met with no critical clarity, accessibility, compatibility or navigation regression. Unknown outcomes, conflicting requirements or an unavailable final gate leave the candidate unaccepted. If preservation needs more context, retain the larger baseline or narrow the authorized objective explicitly; do not sacrifice coverage for the budget.

Retain baseline/candidate identities, the two-way ledger, source conflict decisions, case splits, route inventories/counts, observations, rejected mutants, removals and their reasons, limitations and rollback target. An unchanged task result on a few cases supports only those cases; do not claim universal equivalence, mathematical losslessness or production availability. Return the evidence to the authoring/evaluation caller; existing security, official-validation, lifecycle and publication gates still apply.
