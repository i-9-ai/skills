# Meta-skill collection review

Reviewed on 2026-09-19 against the 23 canonical package entrypoints, their
responsibility boundaries, handoffs, selected implementation/provenance resources,
and rendered sibling icons. This is a semantic collection review; it is not a
model benchmark or a claim that every possible domain skill belongs here.

The repository owns only procedures directly about skills. Tool, framework,
infrastructure and general execution packages belong in a separately authorized
collection. Global package work is outside this repository completion. A package
name alone does not prove this boundary: future additions need the same trigger,
output and consumer review.

No package rename, merge or split is supported by the current triggers and
outputs. Shared vocabulary is deliberate affinity, and the retained handoffs
avoid duplicate implementation ownership. General domain examples in meta-skill
instructions illustrate acceptance criteria; they are not embedded domain
packages. Useful resources stay within their owning packages and remain available
when that topic is selected.

All icons have distinct byte identities. The visual review compares metaphor,
silhouette and small-size legibility as well as palette; color alone is not the
distinction. Structural checks validate SVG safety, raster format and host asset
references. These checks do not imply an accessibility certification.

Revisit this decision map when a package's primary output, consumer, authority
or independently testable responsibility changes. Catalog synchronization checks
the current inventory; this dated decision record does not replace it.
