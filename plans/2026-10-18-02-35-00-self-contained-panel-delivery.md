# Self-contained panel delivery

## Objective and observed failure

Restore the functional panel and retain a runtime that survives changing the
development branch. The installed private lab launches a TypeScript file in the
working checkout; switching to a branch without the panel makes that installation
unavailable. Opening the HTML as a standalone file cannot supply its MCP bridge.

## Scope and authority

Reconcile main into PR107 in the canonical checkout. Extend the existing
preview-first `plugin prepare` operation with explicit panel collection/state
selectors and optional global capability. Retain compiled runtime, original
portable helpers, catalog, UI and the pinned YAML dependency in a new neutral
artifact. Existing skills-only preparation/submission remains unchanged. The
local profile records its local-executor requirement and exact selected paths;
it is never silently passed off as a public skills-only upload.

Update the existing private lab using the supported installation flow while
preserving its identity, collection, proposal state and global permissions.
Verify real global source hashes without changing them. Tests use only disposable
synthetic packages. No host restart, real candidate application, public upload,
review submission, merge, release, marketplace publication or deployment occurs.

## Sequence

1. Resolve the plan-index conflict without losing either branch's responsibilities.
2. Add a bounded inert runtime inventory and extend existing preparation flags.
3. Test an emitted plugin after relocating it and removing its synthetic source;
   initialize its MCP, read the UI/catalog, retain a global proposal, reject
   missing consent, apply with exact approval and recover with separate consent.
4. Verify refusal of missing/stale inputs, linked dependencies and existing output.
5. Document the standalone HTML limitation and native opening path; keep English,
   Portuguese and Spanish availability copy accurate and update the Changeset.
6. Run explicit npm ci, affected tests, full Node24 checks, packed-runtime tests and
   independent exact-commit review; update PR107 and Beads with actual results.
7. Install the retained lab runtime, verify its dependency closure and existing
   state from a fresh process, and separate native operator acceptance from proof
   obtained through a simulated host.

## Distribution boundary

Official desktop-only submission documentation, checked on 2026-10-18, requires
approved-partner organization allowlisting for local MCP submissions. Package
preparation does not establish that eligibility. Keep the complete local runtime
and truthful operator/reviewer instructions ready without fabricating a remote
endpoint or removing the panel from a claimed panel-enabled upload.

Source: https://developers.openai.com/plugins/deploy/desktop-only

## Validation and rollback

No dependency is added. Existing builds compile with TypeScript and the artifact
copies only bounded ordinary files through the collection filesystem repository.
Generated artifact inventories bind retained bytes; no setup, package download or
dependency execution occurs during preparation or startup. Require a clean
explicit build before preparation and exercise both source and npm-installed CLI.

Keep the previous lab version and all proposals for rollback. Reinstall a retained
known-good lab revision through the supported host command; never edit the cache
or discard state. Remove newly introduced preparation flags/components if this
distribution path proves unsupported. Preserve the full original/reverse diff
guards and all historical validation failures.
