# Skill usage MCP

## Objective
Deliver an explicit local stdio interface for observed skill reads and period rankings (issue #17).

## Scope and boundaries
Use Node.js 24 built-ins and SQLite. Persist logical skill, collection, immutable revision, opaque session and event IDs, and timestamps only. Reads are not activations. No hooks, daemon, network, installation, marketplace, NPX publication, or skill execution.

## Sequence
1. Implement bounded MCP initialization and tools.
2. Add checksum-verified ordered transactional migrations and idempotent events.
3. Test concurrent processes, migration rejection, protocol and rankings with disposable fixtures.
4. Document startup, emitter contract and limitations; review the exact change.

## Storage decision
The existing catalog writer replaces database files. Sharing its inode with a direct SQLite writer is unsafe. This first delivery rejects catalog databases and uses a caller-selected dedicated usage database. Consolidation requires migrating catalog writers to a shared transactional storage adapter; it is not silently attempted.

## Validation and removal
Run `node --test tests/skill-usage-mcp.test.mjs`, `npm run check`, `npm run changeset:status`, and `git diff --check`. Verify stdio in a child process. Removing the adapter does not delete caller-owned data. Migration failures roll back and never reset a database.

## Acceptance
Count explicit read events, deduplicate retries, return distinct sessions and bounded half-open period rankings, preserve concurrent inserts, reject unrelated databases and unknown fields. Retain local test evidence; do not claim host activation coverage.
