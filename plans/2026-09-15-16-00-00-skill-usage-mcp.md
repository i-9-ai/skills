# Skill usage MCP

## Objective
Deliver an explicit local stdio interface for observed skill reads and period rankings (issue #17).

## Scope and boundaries
Use Node.js 24 built-ins and SQLite. Persist logical skill, collection, immutable revision, opaque session and event IDs, and timestamps only. Reads are not activations. No hooks, daemon, network, installation, marketplace, NPX publication, or skill execution.

## Sequence
1. Implement bounded MCP initialization and tools.
2. Add checksum-verified ordered transactional migrations and idempotent events.
3. Test concurrent processes, migration rejection, protocol and rankings with disposable fixtures.
4. Document startup, emitter contract and limitations; review the exact change.

## Storage decision
The existing catalog writer replaces database files. Sharing its inode with a direct SQLite writer is unsafe. This first delivery rejects catalog databases and uses a caller-selected dedicated usage database. Consolidation requires migrating catalog writers to a shared transactional storage adapter; it is not silently attempted.

## Validation and removal
Run `node --test tests/integration/cli/skill-usage-mcp.test.mjs`, `npm run check`, `npm run changeset:status`, and `git diff --check`. Verify stdio in a child process. Removing the adapter does not delete caller-owned data. Migration failures roll back and never reset a database.

## Acceptance
Count explicit read events, deduplicate retries, return distinct sessions and bounded half-open period rankings, preserve concurrent inserts, reject unrelated databases and unknown fields. Retain local test evidence; do not claim host activation coverage.

## Transport lifetime completion

Complete the pending-write cancellation finding from PR #28 without a runtime
dependency or forced process exit. A default POSIX pipe/socket output is owned by
the transport through the public `net.Socket` file-descriptor interface. Select
that single write path before initializing `process.stdout`; an already initialized
but unused stdout must not duplicate or retain protocol writes. Finish each valid
response before processing another request, close the owned pipe after orderly
input completion, and destroy a pending write on input failure or premature close.
Retain its error handler through teardown, discard buffered requests after
cancellation, and close storage exactly once. Injected writable streams retain
their explicit seam and must implement the Node writable destruction contract.

Files, terminals and Windows keep Node's existing standard-output path. An OS
write that blocks the event loop synchronously cannot be interrupted by this
adapter; do not claim bounded cancellation for an unread Windows pipe. Verify
natural child-process exit with unread POSIX stdout both before and after its
initialization, intact responses at orderly EOF, late write/destruction errors,
and listener cleanup using disposable fixtures. Revert the transport, focused
tests and lifetime documentation together to remove this correction; never delete
the caller's database.
