# Approved global skill evolution in the panel

## Objective and authority

Let the operator request real improvements to eligible global skills, read the
retained source/candidate diff and apply only after explicit exact-proposal
approval. The user explicitly authorized enabling this functional workflow in
the existing private lab. Preparing or installing it does not approve any real
global skill replacement. Tests must use disposable synthetic global packages.

## Scope and interfaces

- Add an explicit `--panel-global-write` switch to the existing CLI/plugin MCP
  launch, requiring the already explicit global collection and both panel paths.
  Discovery alone remains read only; default configurations retain their behavior.
- Reuse the existing retained-preimage, single SKILL.md replacement, fresh hash
  approval, intent and recovery machinery. Do not build a second mutation engine.
- Resolve source-qualified global IDs against the actual configured collection.
  Only ordinary eligible packages physically inside that root may be edited.
  Reject reserved `.system` paths, linked escapes, unsafe package entries,
  changed source/root identity, state overlap and ambiguous target identity.
- Preserve all existing selected-copy proposals and read-only global review
  records. New global editable records must bind the global root, package identity
  and complete retained revision, and never reinterpret an old entrypoint-only
  review as an approved editable-package request.
- An ineligible global package remains inspectable with an explicit read-only
  reason. Keep portable/full validation distinctions visible. Never execute
  candidate scripts, mutate catalogs, copy globals into the selected collection,
  auto-apply, prune retained evidence or silently edit external symlink targets.
- The UI derives source and editability separately: globals can be eligible or
  read only. Review, Describe a change, current outcome, live comparison, approval
  and separately approved recovery must use the same source-qualified identity.

## Structure and instruction map

Current and target hierarchy stay `AGENTS.md` -> `src/AGENTS.md`,
`tests/AGENTS.md`, `plans/AGENTS.md` and `website/AGENTS.md`. Retain these durable
boundaries and the existing panel operator guide; create no new instruction
scope. Update the source catalog/evolution index summaries for the explicitly
enabled global responsibility, and add this plan to the plans index. Code remains
under the existing singular configuration, repository, service and transport
layers, with class filenames matching their responsibilities.

## Acceptance and evidence

An eligible synthetic global appears with editable source identity. Its user
request returns to a retained global proposal; the panel opens its actual diff,
keeps approval unchecked and refuses an unapproved or stale write. Exact approval
changes only the global SKILL.md; recovery restores its original bytes/mode and
keeps evidence. No selected-copy bytes, sibling/global catalogs or scripts change.
Read-only defaults and existing retained records remain usable. Unsupported
globals explain their limits without disguising source scope as editability.

Retain exact commit, test output, disposable browser captures, independent review,
installed manifest/resource identity and unchanged real global-entrypoint hashes
in local ignored evidence and the linked Beads task. Native user acceptance is a
separate observation from source/protocol/browser checks. Official skill validation
is required only if distributed skill packages change; this scope changes tooling.

## Rollback and exclusions

Remove the explicit switch to disable future global mutation, retain all proposal
state and inspect existing diffs. Revert source/configuration changes together if
needed; never delete original/candidate packages. Recovery of a real applied skill
requires its own freshly reviewed reverse diff and exact operator approval.
No public plugin rollout/submission, registry release, site deployment, host
restart, telemetry enablement or unrelated repository work is authorized here.
