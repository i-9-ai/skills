# Skills Snapshot

## Objective

Provide one portable skill that creates, verifies, lists, and restores a snapshot of a skills collection before a broad local migration.

## Scope

- Snapshot one caller-selected collection or one selected package.
- Store snapshots outside the collection discovery tree.
- Capture a manifest of package identity, file hashes, package layout, and symbolic-link projections.
- Verify a snapshot without mutating the source collection.
- Restore an entire selected collection or package only through an explicit command.
- Provide a Node.js helper with safe defaults and temporary-fixture tests.

## Exclusions

- No automatic snapshot on installation or activation.
- No automatic migration, refactoring, host-link creation, publication, or setup execution.
- No collection-wide credential capture, personal-data collection, or modification of host-managed system packages.
- No deletion of prior snapshots unless an explicit retention command is requested.

## Authority boundaries

Snapshot creation and verification are reversible local operations. Restoration replaces caller-selected local content and therefore requires an explicit restore command and a target confirmation in the command interface. The skill must not modify a host-managed `.system` package unless the caller explicitly selects it and the host permits it.

## Design

The package owns its `SKILL.md`, `scripts/` helper, manifest schema/reference, tests, license, host interface metadata, and distinct icons. The script is idempotent: rerunning snapshot creation with unchanged inputs records an equivalent state without altering source files. A migration coordinator may compose snapshot, audit, and refactor steps, but this skill owns only snapshot lifecycle.

## Implementation sequence

1. Define manifest fields and collision-safe snapshot naming.
2. Implement create, verify, list, and restore commands with explicit source and destination arguments.
3. Make create and verify read-only against the selected collection.
4. Require an explicit restore subcommand and validate manifest integrity before replacement.
5. Add temporary-fixture tests for successful capture, repeat execution, tampering detection, package restore, whole-collection restore, and protected-path refusal.
6. Document normal flow, failure recovery, limitations, and examples inside the package.

## Validation

- Run the package test suite with disposable fixtures only.
- Run the repository catalog generation and repository checks.
- Run `git diff --check`.
- Run the official `skills-ref validate` tool when available; record an unavailable validator as a readiness block rather than a pass.
- Confirm snapshots sit outside discovery and restore does not change excluded paths.

## Rollback

Remove the package from the pull-request branch to revert the feature. For a user collection, use the previously captured snapshot and explicit restore command; do not rely on the installer origin receipt as a rollback mechanism.
