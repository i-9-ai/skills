# Qualify native pilot retention and rollback evidence

Related issue: [#90](https://github.com/i-9-ai/skills/issues/90).

## Objective

Consume the selected Claude client's inert debug alias and report preserved
state separately from selected-source data compatibility. Actual disposable
trials exposed both issues; previous captures and their original outcomes remain
available as historical evidence.

## Scope and authority

Allow only Claude's `native-output/latest` alias to a fixed debug filename for
the selected run, repetition and one of the three observation phases. Reconcile
its target to an ordinary, byte-verified entry in the same exported root after
validating the whole inventory. Keep the alias as data: never follow it, resolve
it against the host, extract it or create a link. Preserve all other alias,
unknown-field, duplicate-entry, traversal and resource limits.

Separate preserved definitions and history from exercised reader/writer
compatibility. The retained newer schema is preserved by rollback, but the
selected older source's readers and writers reject it. Do not label preservation
as full compatibility, downgrade the database, bypass migration guards or infer
compatibility from read-only catalog/resource calls. Report unexercised data
compatibility explicitly, with preservation evidence kept independently.

No provider call, real account profile, installed consumer, marketplace update,
dependency, release or publication is included. Root alone executes authorized
new disposable trials and verifies retained evidence before named cleanup.

## Implementation and validation

1. Bind the retained failures to actual exports, selected source bytes and
   independently reproduced pure validation outcomes.
2. Add the narrowly scoped alias rule and order-independent regular-target
   reconciliation, with malformed, cross-run and missing-target regressions.
3. Update closed observation, driver and report contracts together so preserved
   state cannot become proven data compatibility. Test the unexercised result
   and reject unsupported compatibility claims; the current recipes do not
   exercise an older reader or writer against the preserved newer schema.
4. Check source and source-free compiled fixtures, strict types, formatting,
   repository checks, clean-package tests, Changesets and whitespace.
5. Review the complete executable proposal and exact public commit independently
   before new trials. Keep source validation, actual lifecycle evidence and
   independent native acceptance distinct.

## Acceptance and rollback

The unchanged Claude export can retain its known debug alias without authorizing
arbitrary absolute links. Reports must state both the preservation result and
the limits of selected-source compatibility. Failed historical trials are never
regraded, and native acceptance remains false until its separate evidence gate
is satisfied.

Rollback restores the earlier projector and reporting implementation. No state
migration or evidence deletion is involved.
