# Native observation budget feasibility

Issue: [#90](https://github.com/i-9-ai/skills/issues/90).

## Objective and observed problem

Permit the fixed native observation child to start when the complete input and
preservation checks fit within an explicit phase deadline. Keep preparation,
child execution, rescue, evidence writing and phase completion bounded together.

Two retained disposable Codex repetitions refused to dispatch the selected
observer. Preparation had consumed approximately 2.13 and 2.06 seconds, while
the 45-second phase reserved 42 seconds for that child and two further seconds
for rescue and completion. The remaining preparation allowance was only one
second. The baseline also refused its selected absence observer after about
5.66 and 4.07 seconds. These measurements do not identify the duration of each
individual verification operation. A reported child timeout with unavailable
PID and empty streams was a pre-dispatch budget refusal, not an executed native
client timeout.

The old journals and exports remain unchanged. Their four-gate baseline
candidate result does not establish the separately blocked native hook/MCP
absence observation. Installation evidence does not establish refresh,
rollback, unregistration or complete native acceptance.

## Scope and limits

Change only the outer common observation phase from 45 to 60 seconds. Preserve
the 40-second absolute native lifetime, the 42-second selected-child minimum,
the existing setup/drain/report reserves, one-second child rescue and one-second
phase finish, and the job, command, output, resource and confinement bounds.
The resulting preparation allowance is at most 16 seconds. If the remaining
budget cannot accommodate the complete child and both final reserves, retain a
refusal without spawning it. This is not a retry or an unbounded extension.

Keep the existing single CLI, closed contracts, digest pins, packet validation,
owned process rules, seeded evidence, source witnesses and unsupported gates.
Do not remove repeated integrity checks merely to improve elapsed time. Claude's
separately versioned local-source diagnostic remains a separate proposal and
cannot provide missing native acceptance evidence by changing this limit.

## Authority and implementation

1. Independently reconcile the complete failed exports, Docker receipts,
   process records and exact source that made the refusal. Verify private
   retention before removing only those named disposable resources.
2. Create a new immutable private successor of the reviewed closure. Update the
   outer bound and meaningful budget tests, preserving all original snapshots
   and reviews. Generated preparation may copy only an exact verified baseline
   into a fresh owned private workspace; source edits use the normal editor.
3. Obtain independent whole-source review of that successor before executing
   it. Use new run identities and fresh owned offline containers for each
   repetition. Never reinterpret an earlier failed capture as passing.
4. Port only the bounded configuration, tests and relevant documentation into
   the canonical repository. Reconcile compiled distribution and the existing
   public route; keep private binaries and raw observations outside Git.
5. Run repository checks, clean consumer packaging, Changesets validation,
   exact-commit independent review and required CI. Report source validation,
   actual native observations and unsupported acceptance independently.

Existing authority covers these bounded disposable tests and the repository
delivery. It does not cover real-user profiles, provider calls, credential use,
external repository creation, release publication or marketplace submission.

## Verification and rollback

Test the measured preparation durations, dispatch at the exact remaining-budget
boundary, refusal just beyond that boundary, non-finite or negative elapsed
values, ordinary-child caps and unchanged inner lifetime/reserves. Every
dispatched child plus preparation and both final reserves must fit within the
60-second outer phase. Fake executors must prove that a refusal never spawns a
process. Run `npm run check`, consumer packaging tests,
`npm run changeset:status` and `git diff --check` under Node 24 after `npm ci`.

Retain failures, unrun phases, byte identities and cleanup observations. A manual
fallback must name any unsupported gate and the exact evidence still needed;
it cannot claim that filesystem configuration proves native execution.

Reverting the exact configuration/test/documentation change restores the old
45-second behavior without changing retained evidence or installed user state.
No new instruction scope, dependency, migration or public command is required.
